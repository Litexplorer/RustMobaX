# 产品定位与范围

## 一句话

RustMobaX 是**跨平台的远程工作台**：一个窗口里同时握着 SSH 会话、本地/串口终端、SFTP 文件面板、
端口转发和网络工具箱，用来替代 MobaXterm 在工程场景中的位置。

## 要解决的真实痛点

MobaXterm 好用，但它在三点上持续放血：

1. **平台**。只有 Windows。mac/Linux 用户被迫拼装：Termius（贵、无 X11）+ FileZilla（割裂）+ 命令行 ssh。
2. **限制**。免费版锁会话数、锁隧道数、锁多执行，团队里"能开几个标签"成了协作障碍。
3. **不可控**。闭源、自带 Cygwin 运行时、无法嵌入自有流程（跳板机策略、审计、凭据托管）。

RustMobaX 的赌注：**这些能力的 80% 可以用纯 Rust 实现**，剩下 20%（X11 server、RDP 完整栈）
明确分阶段、明确降级，而不是一次做全。

## 目标用户

| 用户 | 画像 | 最在意的三件事 |
| --- | --- | --- |
| SRE / 运维 | 管 20–200 台机器，日常跳板机 + 批量执行 | 会话可组织、多执行、隧道稳 |
| 后端开发 | 本地写码、远程跑服务，频繁传文件 | 终端体验、SFTP 跟随目录、拖拽上传 |
| 数据 / 科研 | 服务器上跑 GUI 程序（ParaView、MATLAB） | X11 转发一键可用 |
| 网络 / 嵌入式 | 串口调交换机、路由器、开发板 | 串口终端、Telnet、日志保存 |
| 教学 / 学生 | 实验室共享机器、要便携 | 免安装、会话导入导出 |

## 核心使用场景（Job To Be Done）

1. **一句话连上机器**：从会话列表点一下，30 秒内出现可用终端，不用记端口和私钥路径。
2. **改文件不用离开窗口**：左边 SFTP 跟着终端 `cd` 走，双击文件就地编辑，保存即回传。
3. **一次操作一批机器**：把同一段命令发给 5 台机器，看到 5 份输出。
4. **图形程序像本地一样跑**：`ssh -X` 之后直接弹窗，不用先折腾 X server。
5. **临时救火**：给个 IP 就能 ping / traceroute / 查端口 / 查 DNS，不用切窗口。

## 范围（Scope）

### 首版必须做（P0）

- SSH2 会话（密码 / 私钥 / Agent / 二次跳转的单跳 ProxyJump）
- 多标签 + 分屏终端，xterm.js 渲染，256 色 / TrueColor / 鼠标事件 / 粘贴保护
- 本地 Shell 会话（Windows PowerShell/WSL，mac/Linux 默认 shell）
- SFTP 侧栏：列目录、上传、下载、重命名、删除，双击用内置编辑器
- 会话管理：分组、搜索、导入导出（兼容 MobaXterm `.mxtsessions` 尽力解析）
- 凭据库：主密码解锁，私钥与密码加密落盘
- 端口转发：本地转发 / 远程转发 / 动态 SOCKS5

### 第二阶段（P1）

- X11 转发（先外挂系统 X server，再评估内嵌）
- 多执行（MultiExec）、跨会话命令广播
- 网络工具箱：ping / traceroute / DNS / whois / 端口探测
- 宏录制与回放
- 串口终端、Telnet

### 第三阶段（P2）

- RDP / VNC 会话（`ironrdp` / `vnc-rs`）
- 内置 X11 server（自研或绑定 xorg-server）
- 会话同步与团队共享（可选自托管后端）
- 插件机制

## 明确不做（Non-Goals）

- **不做 IDE**：不提供代码补全、调试器、项目构建。
- **不做云控制台**：不管理 K8s 集群、不替代云厂商 Web 终端。
- **不做通用远程桌面**：RDP/VNC 只做"能连、能看清、能键鼠"，不做多显示器与打印机重定向。
- **不做 SaaS**：默认本地存储，不强制登录账号。
- **不在首版支持 SSH1 / rlogin / 老旧不加密协议**。

## 差异化定位

不做"MobaXterm 的像素级复制"，做三件 MobaXterm 做不到的事：

1. **真跨平台**，且三端会话库格式一致，可同步。
2. **无功能阉割**：隧道数、会话数、多执行全部放开。
3. **可嵌入**：核心以库的形式暴露（`rustmobax-core`），允许被 CI、审计系统调用。
