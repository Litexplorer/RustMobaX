# 路线图

里程碑按"可用闭环"划，不按功能堆叠划。每个里程碑都必须能被人真正用起来。

## 总览

| 里程碑 | 目标 | 周期 | 故事范围 |
| --- | --- | --- | --- |
| M0 骨架 | 跑得起来、结构立住 | 1–2 周 | US-301、US-1001、US-1002（部分） |
| M1 MVP | 替代 MobaXterm 的日常 80% | 6–8 周 | 全部 P0 |
| M2 生产力 | 补齐批量与诊断能力 | 6–8 周 | 大部分 P1 |
| M3 补齐 | 远程桌面与生态 | 8 周+ | P2 + 长尾 P1 |

---

## M0 骨架（1–2 周）

**目标**：证明技术栈成立，把最容易塌的地基先踩一遍。

交付：

- Tauri 2.x + React + TS 脚手架，三平台能起
- 会话数据模型与 SQLite 层落地（增删改查 + 迁移脚本）
- 本地 PTY 会话端到端跑通：开标签 → 敲命令 → 有输出 → 能 resize
- 终端渲染基线：TrueColor、中文宽字符、`vim` / `htop` / `tmux` 无花屏
- 主题与快捷键框架
- CI：三平台 `cargo check` + `bun run build` + 冒烟测试

**退出标准**：在一台干净机器上，双击启动后 30 秒内能开一个本地终端并正常用 `vim`。

**不做**：SSH、SFTP、凭据库、隧道。

---

## M1 MVP（6–8 周）

**目标**：一个日常真的能用的版本。用户可以把 MobaXterm 换成它而不回退。

交付（全部 P0）：

| 能力 | 覆盖故事 |
| --- | --- |
| 会话管理：新增/分组/搜索/导入 | US-101、102、103、105 |
| SSH 连接：三种认证、指纹校验、错误分类 | US-201、603、604 |
| 终端体验：多标签、分屏、搜索、粘贴保护 | US-202、203、204、205、206 |
| 本地终端也进同一套体验 | US-301 |
| SFTP：侧栏、cwd 跟随、上传下载、基本操作、内置编辑器 | US-401–405 |
| 凭据库：主密码、加密落盘 | US-601、602 |
| 隧道：本地/远程/SOCKS5/跳板机 | US-501、502、503、505 |
| 主题与快捷键 | US-1001、1002 |

**现状（2026-11-02）**：会话管理、本地终端、SSH（密码/私钥/指纹三态/一跳跳板）、凭据库、
终端体验（分屏/搜索/粘贴保护）、SFTP 文本级、隧道（本地/远程/SOCKS5）已交付；
SFTP 二进制传输、隧道持久化、前端跳板机入口尚未完成。本轮补上设置与外观（主题/缩放/终端字号）
与 SFTP 停靠面板，`src-tauri` 只做过垫片 `cargo check`，桌面端验收待补。

**退出标准**（必须全部满足才发布）：

1. 三个真实场景跑通：① 通过跳板机连内网机器并改远端配置；② 传 1 GB 文件不断线；③ 开 5 个隧道过夜不断。
2. 终端吞吐达标：`cat` 10 MB 文本无丢字节、UI 不卡（见 architecture 性能目标）。
3. 凭据库文件用 `strings` 扫不出任何明文密码。
4. 三平台各完成一轮手工回归，阻断级缺陷为零。

**不做**：X11、多执行、网络工具箱、串口、Telnet、RDP/VNC。

---

## M2 生产力（6–8 周）

**目标**：从"能用"到"比别人顺手"。这一期决定用户是否长期留下。

交付（P1）：

- **X11 转发**：US-901、902（外挂系统 X server；Windows 引导安装 VcXsrv）
- **多执行**：US-801、802
- **网络工具箱**：US-701、702、703、704
- **串口与 Telnet**：US-302、303、304
- **宏录制**：US-803、804
- **传输增强**：US-406、407
- **体验补齐**：US-207、208、504、605

**退出标准**：

1. 一次向 10 台机器广播命令，汇总结果准确率 100%（不靠猜）。
2. X11 场景跑通：远程 `xeyes` / `ParaView` 能在本地显示。
3. 串口连真实交换机可交互，波特率切换生效。
4. 断网 30 秒后隧道自动恢复，无需人工干预。

**不做**：内嵌 X server、RDP/VNC、目录同步、插件。

## M3 补齐（8 周+）

**目标**：覆盖长尾需求，扩大适用人群。

交付：

- **远程桌面**：US-1101、1102、1103（先做降级路径，再自研）
- **内嵌 X server**：US-903（先做可行性验证，不通过的结论也要留档）
- **目录同步**：US-408
- **工程化**：US-1003、1004、1005、1006
- **凭据审计**：US-606
- **剩余 P1**：US-104、106、505 多跳

**退出标准**：功能矩阵里除"明确不做"外，无遗留未评估项；每项要么交付，要么有书面不做的理由。

---

## 排序依据（为什么是这个顺序）

1. **先证伪风险最大的假设**。终端渲染与 IPC 吞吐是所有功能的地基，M0 就压测它。
2. **P0 定义在"能否替代"上，不是"功能是否多"**。少一个 X11 用户还能忍，少一个 SFTP 面板用户就走。
3. **X11 放 M2 不放 M1**。它的链路实现不难，但 Windows 端体验依赖外部组件，容易把 MVP 拖成无底洞。
4. **远程桌面永远最后**。这是最容易变成"第二个项目"的地方，且有系统客户端可用。

## 里程碑风险

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| M0 终端渲染不达标 | `vim` 花屏、中文错位 | 优先换渲染方案（webgl addon → canvas → alacritty 内核） |
| IPS 吞吐不达标 | `yes` 时 CPU 打满、输入延迟 | 立即改二进制 Channel + 自建回环 WebSocket |
| `russh` 兼容性踩坑 | 特定服务端握手失败 | 保留 `ssh2` 作为第二后端，用 trait 隔离 |
| SFTP cwd 跟随碎片化 | 多种 shell 上报方式不一 | 收敛为"OSC 7 优先 + PROMPT_COMMAND 兜底 + 手动刷新" |
| X11 在 Windows 体验崩 | 引导安装失败率高 | 接受降级，明确写进文档，不硬扛 |

## 交付纪律

- 每个里程碑末尾留一篇 `docs/retro-<Mn>.md`，记录做偏了什么、砍了什么、下次不做什么。
- 故事状态只在"验收标准全部可测通过"时才允许标完成，不接受"基本能用"。
